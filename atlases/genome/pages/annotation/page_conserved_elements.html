▰ Conserved elements — UCEs / phastCons
Stage: annotation · spec / phase C–D · driven by conserved_elements
What this page shows
spec · phase C–D
Ultra-conserved elements (UCEs) and phastCons-derived conserved regions rendered as a regulatory-disruption sub-track. Scores how much conserved sequence each inversion candidate overlaps — a candidate that disrupts a UCE has a different functional weight than one that doesn't, independent of gene content.
Complements page_genes (gene cargo) by counting regulatory hits, not just coding hits.

View 1 — per-chrom UCE tick strip
mockup · LG01 shown
Each tick = one ultra-conserved element (UCE) above the 200 bp / 95%- identity cut. Width matches the Inversion Atlas scrubber.
UCE definition follows Bejerano et al. 2004 with the 200 bp / 95% identity cut adapted to a teleost-internal alignment (anchor = Danio rerio with Cgar / Cmac / Ipun in the alignment). The full UCE set is in conserved_elements.bed; this view paginates by activeChrom.

View 3 — phastCons score profile
mockup · LG03 around cgar_inv_002
Continuous phastCons posterior probability (0–1) across a 5.7 Mb window. Peaks above 0.95 are flagged as conserved regulatory elements; the highest peaks usually overlap UCEs (downward-pointing ticks in the strip above).
7 distinct phastCons peaks ≥ 0.95 visible in the cgar_inv_002 span. Each peak that does NOT coincide with a known UCE flags as a "novel conserved element" — these are the candidates the comparative-genomics supplement focuses on.
Import schema — conserved_elements layer
BED + bedGraph
# Layer is split into TWO files:
#
# 1) conserved_elements.bed         (UCEs — discrete elements)
#    Standard 6-column BED:
#       chrom  start  end  name   phastCons_max  strand
#    Example:
LG01   1418520    1418720    UCE_00001   0.998   .
LG01   2418720    2419120    UCE_00002   0.991   .
LG01   2419520    2419650    UCE_00003   0.974   .
LG03  14820100   14820310    UCE_00045   0.998   .
LG03  15820440   15820640    UCE_00047   0.996   .
#
# 2) conserved_elements.phastcons.bedgraph   (continuous score profile)
#    bedGraph (chrom, start, end, value) — one row per non-zero phastCons bin.
#    Example (10 kb bins):
LG03  12400000  12410000  0.42
LG03  12410000  12420000  0.58
LG03  12420000  12430000  0.74
LG03  12480000  12490000  0.96
LG03  12490000  12500000  0.98
LG03  12500000  12510000  0.94
#
# The renderer materializes (1) into per-chrom tick arrays for View 1 +
# overlap counts for View 2, and (2) into the continuous profile path
# for View 3. activeChrom drives both materializations.
