What this page shows
spec · phase B (primary deliverable)
One row per chromosome, length-scaled across the page width. Each row stacks four density tracks: gene density, repeat density, conserved-element density, and the active cohort's L2 envelopes + promoted candidates (read cross-atlas from the Inversion Atlas's candidates_registry). Hover for per-window values; click a row to drill into the per-chromosome detail view (future page).
This is the Genome Atlas's main "map of the map" — the page that makes the assembly tangible. Mirror the Inversion Atlas's scrubber width so users can mentally align the two side-by-side.

The strip is length-scaled: LG01 sets the 100% width and the smaller chroms scale proportionally so a reader can spot length-vs-content trends at a glance. Each row stacks 4 sub-tracks (base + gene + repeat + CO); the cohort overlay sub-track (row 5 of the design below) is drawn on hover when an Inversion-Atlas candidate intersects the chrom. The Mac haplotype renders in an identical strip; the toolbar toggles between them.
Sub-track stacking order
design note
1. base bar
Length-scaled chromosome backbone. Centromere band overlay from centromere_telomere; telomere chips at each end.
2. gene density
Coral-gradient stripe. 100 kbp bins. Reads from gene_track; telomere-biased pattern is the expected catfish baseline.
3. repeat density
Rust-gradient stripe. Same binning. Reads from repeat_track; peri-centromeric peak is the expected EDTA pattern.
4. CO density
Rose-gradient stripe. Sex-collapsed CO-event density from crossover_track; clicking pivots to page_crossovers filtered to the corresponding candidate.
5. cohort overlay
L2 envelope rectangles + candidate markers from the Inversion Atlas. Drawn on hover when shared.candidate intersects this chrom; otherwise hidden.
Import schema — chromosome_map.json
JSON Schema · draft-2020-12

  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "chromosome_map.schema.json",
  "title": "Chromosome map + density sub-tracks — per-haplotype",
  "description": "One file per haplotype.   "type": "object",
  "required": ["haplotype", "bin_size_bp", "chroms"],
  "additionalProperties": true,
  "properties": {
    "haplotype":   { "type": "string", "description": "fClaHyb_Gar | fClaHyb_Mac" },
    "bin_size_bp": { "type": "integer", "minimum": 1000, "description": "Bin width for the density tracks. Typical: 100000." },
    "chroms": {
      "type": "array",
      "items": { "$ref": "#/$defs/chrom" }
    }
  },
  "$defs": {
    "chrom": {
      "type": "object",
      "required": ["id", "length_bp", "n_bins"],
      "additionalProperties": true,
      "properties": {
        "id":                  { "type": "string" },
        "length_bp":           { "type": "integer", "minimum": 0 },
        "n_bins":              { "type": "integer", "minimum": 1 },
        "centromere_bp":       { "type": ["integer", "null"], "description": "Mean centromere position in bp; null if not localized." },
        "centromere_half_width_bp": { "type": "integer", "description": "Centromere band drawn as [centromere_bp ± half_width]." },
        "telomere_L":          { "type": "boolean", "description": "5' (start-of-chrom) telomere detected by tidk." },
        "telomere_R":          { "type": "boolean" },
        "is_t2t":              { "type": "boolean", "description": "centromere_complete && telomere_L && telomere_R." },
        "gene_density": {
          "type": "array",
          "description": "Bin-aligned [0..1] normalized gene density. length == n_bins.",
          "items": { "type": "number", "minimum": 0, "maximum": 1 }
        },
        "repeat_density":     { "type": "array", "items": { "type": "number", "minimum": 0, "maximum": 1 } },
        "conserved_density":  { "type": "array", "items": { "type": "number", "minimum": 0, "maximum": 1 } },

The strip rendered above is driven by exactly this schema. The bin arrays are normalized to [0..1] on the cluster side (so the renderer doesn't need to know the max bin value across all chroms before it can draw the first row); the CSS gradient stops are computed from each bin's normalized value.
